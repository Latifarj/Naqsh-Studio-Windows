# نسخهٔ دسکتاپ Windows

نقش‌یار اکنون یک پوستهٔ Electron برای ویندوز دارد. رابط وب (`web/`)، موتور هندسهٔ مشترک (`shared/engine.js`)، کتابخانهٔ نقش‌ها و API محلی PDF همان فایل‌های پروژه‌اند؛ پوسته فقط سرور محلی را بالا می‌آورد و پنجرهٔ دسکتاپ را به آن وصل می‌کند. بنابراین تغییرات رابط یا موتور به شاخهٔ جداگانهٔ دسکتاپ نیاز ندارند و همان رابط می‌تواند بعداً در وب منتشر شود.

## اجرای توسعه روی Windows

پیش‌نیازها: Node.js نسخهٔ ۲۰ یا جدیدتر، Python 3.10 یا جدیدتر و وابستگی‌های CairoSVG پروژه. در PowerShell، از ریشهٔ پروژه اجرا کنید:

```powershell
py -3 -m pip install -r requirements.txt
npm ci
npm run desktop
```

برای توسعهٔ معمول وب همچنان `py -3 server.py` و نشانی `http://127.0.0.1:8765` کار می‌کنند. Electron برای هر اجرای دسکتاپ از یک پورت آزاد روی `127.0.0.1` استفاده می‌کند؛ سرور به شبکهٔ بیرونی bind نمی‌شود.

## ساخت نصاب Windows

نصاب x64 با `npm run dist:win` ساخته می‌شود و در `release/win/` قرار می‌گیرد. این فرمان یک نسخهٔ مستقل از سرور پایتون می‌سازد و سپس آن را همراه Electron در نصاب NSIS می‌گذارد. ساخت سرور نیازمند Python، `requirements-desktop.txt` و فایل‌های DLL کتابخانهٔ Cairo است؛ ساده‌ترین راه، اجرای workflow ویندوزیِ `.github/workflows/build-windows.yml` است. آن workflow آزمون‌ها را اجرا می‌کند و نصاب را به‌صورت artifact قابل‌دانلود نگه می‌دارد.

برای ساخت محلی، MSYS2 را نصب و بستهٔ `mingw-w64-x86_64-cairo` را اضافه کنید، سپس در PowerShell مسیر `C:\msys64\mingw64\bin` را به `CAIRO_DLL_DIR` بدهید:

```powershell
$env:CAIRO_DLL_DIR = 'C:\msys64\mingw64\bin'
py -3 -m pip install -r requirements-desktop.txt
npm ci
npm run dist:win
```

این محیط توسعه گواهی امضای کد ندارد؛ Windows ممکن است برای نصاب ساخته‌شده توسط خودتان هشدار ناشر ناشناس نشان دهد. این هشدار نشانهٔ آزموده‌شدن یا امضای تجاری محصول نیست.

## ساختار و اصول امنیت

- `desktop/main.cjs` فقط سرور بسته‌بندی‌شده را اجرا می‌کند، تا آماده‌شدن `/api/health` صبر می‌کند و پنجره را با `nodeIntegration` خاموش، `contextIsolation` روشن و sandbox فعال باز می‌کند.
- `desktop/server.spec` رابط وب و داده‌ها را داخل سرور مستقل می‌گذارد. وابستگی‌های native لازم برای تبدیل PDF نیز از Cairo همراه آن بسته‌بندی می‌شوند.
- دانلودهای SVG، PDF و JSON از پنجرهٔ ذخیرهٔ بومی Windows عبور می‌کنند. داده‌های پروژه در مرورگر محلی و روی دستگاه می‌مانند؛ حساب کاربری یا همگام‌سازی ابری به برنامه افزوده نشده است.
- APIهای موجود (`/api/health` و `/api/export/pdf`) مشترک باقی می‌مانند. قابلیت‌های اختصاصی سیستم‌عامل باید در `desktop/` بمانند و وارد `shared/engine.js` نشوند.
- برای نسخهٔ وب، سرور فعلی Python و همان پوشه‌های `web/`, `shared/`, و `assets/` استفاده می‌شوند. از این رو، جداکردن backend یا انتشار وب آتی نیازی به کپی‌کردن موتور چیدمان ندارد.

نصاب Windows باید روی یک دستگاه Windows واقعی نصب و اجرا شود؛ ساخت CI، آزمون‌های پروژه یا شبیه‌سازی API به‌تنهایی تأیید نصب روی همهٔ نسخه‌های Windows نیست.
